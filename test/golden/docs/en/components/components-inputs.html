TextField

A text field: helper, icon, error and enabled.
Helper
Icon
Error
Enabled

A text field with a label, helper text and an icon. Every keystroke reaches onChanged.

ParameterWhat it does
decorationInputDecoration: labelText, hintText, helperText, errorText, prefixIcon, suffixIcon, prefixText, suffixText, counterText, filled, isDense
onChanged, onSubmittedthe method that receives the text, on every keystroke or when Enter is pressed
controllera TextEditingController from the ViewModel, to read or change the text from a method
keyboardType, obscureTextthe phone keyboard (emailAddress, phone, number) and the hidden text of a password
maxLines, minLinesmultiple lines; maxLines: null grows as you type
initialValue, enabledthe initial value; false disables the field

The remaining attributes (readOnly, maxLength, textInputAction, autofillHints) are in Forms.

A form field: it validates with its rules and shows the message of the first one that fails. Validator includes required, email, minLength, maxLength, pattern, min, max and custom.

With a field from a FormSchema (TextFormField(field: SignUp.email)), the server checks the same rules on submit (Forms).

Autocomplete

A field that suggests options: the list, which way it opens and its height.
List
Fruits
Colors
Opens
Down
Up
Panel height
200 px

A field that suggests options as the user types, in a panel that sits above the rest of the page. The arrow keys move the highlight, Enter picks and Esc closes; without JavaScript it is a plain text field.

A screen reader announces how many options there are every time they change. These texts are translated with three parameters:

Autocomplete<String>(
  resultsLabel: '{count} results',
  oneResultLabel: '1 result',
  noResultsLabel: 'No results',
  optionsBuilder: (value) =>
      fruits.where((f) => f.contains(value.text.toLowerCase())),
)
ParameterWhat it does
optionsBuilderthe options; called once, when the page is built
displayStringForOptionan option's text: what is shown and what is matched
onSelectedthe method that receives the option (String, number, bool or enum)
optionsViewOpenDirection, optionsMaxHeightwhich way the panel opens and its maximum height
semanticLabel, menuStylethe field's accessible name and the panel's look
Difference from Flutter

optionsBuilder can't be async, and no option is highlighted until the user moves the highlight, so Enter submits what was typed.

Suggestions from the server

For options the server looks up, RawAutocomplete shows a ViewModel list in the panel:

RawAutocomplete<String>(
  optionsBuilder: (v) => const [],
  textEditingController: search.box, // a TextEditingController of the view model
  focusNode: search.focus,
  fieldViewBuilder: (context, controller, focus, submit) =>
      TextField(controller: controller, focusNode: focus, onChanged: search.type),
  optionsViewBuilder: (context, onSelected, options) => Watch.list(
    search.names,
    itemKey: search.nameOf,
    each: (row) => Semantics(
      role: SemanticsRole.option,
      child: row.link(search.hrefOf, child: row.text(search.nameOf)),
    ),
  ),
)

Command palette (inline)

For a ⌘K palette inside a dialog, the list sits in the flow next to the field instead of a floating panel:

RawAutocomplete<String>(
  inline: true,          // list in the flow, visible while there are options
  highlightFirst: true,  // the first option is active: Enter picks it
  optionsBuilder: (v) => const [],
  fieldViewBuilder: (context, controller, focus, submit) =>
      TextField(controller: controller, focusNode: focus),
  optionsViewBuilder: (context, onSelected, options) => Watch.list(
    palette.hits,
    itemKey: palette.idOf,
    each: (row) => Semantics(role: SemanticsRole.option, child: row.text(palette.nameOf)),
  ),
)

Inline, the list does not take Esc: the dialog closes with one press. Keys: Up/Down wrap, PageUp/PageDown move a page, and Ctrl or Cmd with Home/End jump to the first or last option (plain Home/End keep moving the field's caret, as in the WAI-ARIA combobox pattern). highlightFirst also works without inline.

Date fields

The browser's field or the field with a calendar. Months, days, first day of the week and digits come from the page's language.
Field
Native
Calendar
Allows empty

InputDatePickerFormField is the browser's date field. DatePickerFormField adds a button that opens a calendar and hands the date to the ViewModel with onDateChanged.

The calendar uses the page's language: names, first day of the week, digits and direction (Languages).

Difference from Flutter

There is no showDatePicker(context): the calendar lives in the page. Use DatePickerFormField, or a DatePickerDialog opened with DialogTrigger (Feedback).

Value bubble

SliderThemeData(showValueIndicator:) draws a bubble over the thumb that follows it while dragging. label is its text: a {} is replaced by the live value.

import 'package:thor_ui/thor_ui.dart';

class SliderBubbleDemo extends StatelessWidget {
  const SliderBubbleDemo({super.key});

  @override
  Widget build(BuildContext context) => Theme(
    data: ThemeData(
      sliderTheme: const SliderThemeData(
        showValueIndicator: ShowValueIndicator.alwaysVisible,
      ),
    ),
    child: const SizedBox(
      width: 320,
      child: Slider(
        value: 50,
        min: 10,
        max: 100,
        divisions: 9,
        label: '{}k',
        semanticLabel: 'Visitas al mes',
      ),
    ),
  );
}

Difference from Flutter

the bubble is CSS that follows the thumb: there is no valueIndicatorShape. Without showValueIndicator in the theme, label is only the tooltip.

Difference from Flutter

value is the value the server rendered the page with. After that, the control moves on its own and notifies the ViewModel with onChanged; to show the value somewhere else, read it with Watch.
