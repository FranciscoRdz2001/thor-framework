Posición del toque

onTapDown y onTapUp reciben la posición en píxeles desde la esquina superior izquierda del elemento. Un lienzo es un solo elemento y el método sabe dónde dibujar.

onTapDown se llama al bajar el puntero, aunque el toque termine en un arrastre. onTapUp solo se llama si el toque termina como toque: no tras moverse más de 8 px, deslizar o mantener. Con el teclado, Enter o Espacio sobre el elemento enfocado es un toque en su centro.

Diferencia con Flutter

Gesture entrega x e y como dos números; GestureDetector entrega TapDownDetails y TapUpDetails. onTap se llama al instante aunque haya onDoubleTap. Los callbacks son métodos de un ViewModel (ThorState), no closures.

Gesture no agrega elementos: se aplica al elemento de su hijo. Si el hijo no es un botón ni un enlace, le da el rol de botón y el manejo de teclado. Un deslizamiento horizontal deja pasar el desplazamiento vertical de la página, y al revés.

Importante

Mientras dura el arrastre, el desplazamiento y la escala del gesto reemplazan los que tenga el elemento. Con movimiento reducido, feedback: Press() escala sin animar.

Deslizar

Deslizar es un gesto de trazo, y las pautas de accesibilidad (WCAG 2.5.1) piden otra forma de hacerlo: onSwipe responde también a Mayús + flecha. Agrega además un botón visible para la misma acción.

GestureDetectorRecibe
onTap, onDoubleTap, onLongPresslo mismo que en Gesture
onTapDown, onTapUpTapDownDetails, TapUpDetails (localPosition)
onPanUpdateDragUpdateDetails (delta)
onPanEndDragEndDetails (velocity, localPosition, globalPosition; primaryVelocity es null, como en un pan)
onHorizontalDragEnd, onVerticalDragEndSwipeDirection en ese eje
onScaleEndla escala

Los callbacks que el navegador no puede entregar (onTapCancel, onPanStart, onScaleUpdate…) están marcados @Deprecated y fallan al renderizar con THOR-R040, que indica qué usar.

InkWell no dibuja ondas: al pasar el puntero, con foco y al presionar muestra una capa translúcida (hoverColor, focusColor, highlightColor). borderRadius y customBorder la redondean; InkResponse la dibuja como círculo. Sin onTap, onDoubleTap ni onLongPress no responde, como en Flutter.

Hijo de InkWellResultado
texto, ícono o imagenun botón nativo
una caja (Container, Row, Card…)rol de botón, foco, Enter y Espacio
un botón (FilledButton, IconButton…)el botón del hijo, sin rol nuevo
Importante

Un control dentro de una caja con InkWell sigue siendo su propio botón, pero un lector de pantalla anuncia un botón dentro de otro. Saca el control del área que se toca.

import 'package:thor_ui/thor_ui.dart';

class ArchiveViewModel extends ThorState {
  final rows = state(const [1, 2, 3]);
  final last = state('Swipe a row to either side');

  String label() => last.value;
  String rowKey(int n) => 'r$n';
  String title(int n) => 'Order #${1040 + n}';

  Future<bool> sure(String key, DismissDirection direction) async =>
      direction == DismissDirection.endToStart || key != 'r1';

  void archived(String key, DismissDirection direction) => batch(() {
    rows.value = [
      for (final n in rows.value)
        if (rowKey(n) != key) n,
    ];
    last.value = '$key: ${direction.name}';
  });
}

final archive = ArchiveViewModel();

Dismissible(
  key: ValueKey(m.id),
  direction: DismissDirection.endToStart,
  onDismissed: inbox.archived.withArg(m.id),   // void archived(int id, DismissDirection d)
  confirmDismiss: inbox.ask.withArg(m.id),     // Future<bool> ask(int id, DismissDirection d)
  background: const ColoredBox(color: Color(0xFF16A34A)),
  child: MessageTile(m),
)
ParámetroUso
onDismissedmétodo del ViewModel que quita la fila; recibe la DismissDirection
confirmDismissdevuelve bool o Future<bool>; false devuelve la fila a su lugar
directionhorizontal (por defecto), vertical, startToEnd, endToStart, up, down o none
background, secondaryBackgroundel primero para startToEnd y down; el segundo para endToStart y up
dismissThresholdsumbral por dirección ({DismissDirection.endToStart: 0.7})
resizeDuration, movementDurationel pliegue (null: sin pliegue) y el deslizamiento
Diferencia con Flutter

No existen onUpdate, onResize, crossAxisEndOffset ni dragStartBehavior. Sin JavaScript la fila es solo su hijo: ofrece la misma acción en un botón.

  • Datos: llegan al método del destino como String, número, bool o enum; un Map o una List, como JSON. onWillAcceptWithDetails decide si caben.
  • Destino: builder corre una vez en el servidor. overStyle se aplica mientras hay encima algo que cabe y rejectStyle, algo que no.
  • LongPressDraggable: espera una pulsación (delay, 500 ms) para que moverse antes desplace la página. Conviene en listas con desplazamiento.
  • Callbacks: onDragStarted, onDragCompleted, onDraggableCanceled y onDragEnd en el origen; onLeave y onMove en el destino.
  • Bordes: cerca del borde, la página o el contenedor se desplazan solos.

Con el teclado (WCAG 2.5.7), Espacio o Enter levanta el origen, las flechas recorren los destinos que lo aceptan, Espacio o Enter lo suelta y Esc cancela. Un lector de pantalla anuncia cada paso; labels: DragLabels(...) traduce las frases.

Diferencia con Flutter

No existen onDragUpdate por cuadro, rootOverlay ni ignoringFeedbackSemantics, y se arrastra un elemento a la vez. El feedback no toma el tamaño del origen: dale el suyo. Sin JavaScript no se arrastra.

ReorderableListView

El usuario arrastra el asa de un elemento para cambiar el orden. onReorder(oldIndex, newIndex) usa los índices de Flutter: newIndex cuenta la lista antes de quitar el elemento, así que al bajar se resta uno.

header y footer no son elementos: se dibujan junto al elemento role="list", no dentro, así que la lista contiene solo sus elementos. Se desplazan con los elementos, como en Flutter, y padding rodea a los tres.

import 'package:thor_ui/thor_ui.dart';

class MotionPlanViewModel extends ThorState {
  final steps = state(const ['Grind', 'Strain', 'Serve', 'Wash']);

  String order() => steps.value.join(' → ');
  String stepKey(String s) => s;
  String stepTitle(String s) => s;

  void reorder(int oldIndex, int newIndex) => batch(() {
    final list = [...steps.value];
    final moved = list.removeAt(oldIndex);
    list.insert(newIndex > oldIndex ? newIndex - 1 : newIndex, moved);
    steps.value = list;
  });
}
