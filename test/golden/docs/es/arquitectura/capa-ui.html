Capa de interfaz

Escribe la vista como un widget y el ViewModel en dos mitades: un ThorState para lo que cambia en el navegador, y load y las acciones para el servidor.

Es un widget: muestra lo que el ViewModel le da y le pasa lo que hace el usuario. QueryBuilder renderiza la espera, el error y los datos; el botón llama a un método del ViewModel.
class OrdersView extends StatelessWidget {
  const OrdersView({super.key, required this.viewModel});

  final OrdersViewModel viewModel;

  @override

  Widget build(BuildContext context) => ListenableBuilder(
    listenable: viewModel.load,
    builder: (context, child) {
      if (viewModel.load.running) {
        return const Center(child: CircularProgressIndicator());
      }
      if (viewModel.load.error) return const Text('Could not load');
      return child!;
    },
    child: ListenableBuilder(
      listenable: viewModel,
      builder: (context, _) => ListView(
        children: [
          for (final order in viewModel.orders)
            ListTile(
              title: Text(order.title),
              trailing: TextButton(
                onPressed: () => viewModel.cancel.execute(order.id),

                child: const Text('Cancel'),
              ),
            ),

        ],

      ),

    ),

  );
}
class OrdersView extends StatelessWidget {
  const OrdersView({super.key, required this.viewModel});

  final OrdersViewModel viewModel;

  @override

  Widget build(BuildContext context) => QueryBuilder<List<Order>>(
    query: viewModel.list,
    builder: (context, snapshot) {
      if (snapshot.hasError) return QueryError(viewModel.list);
      if (!snapshot.hasData) return const Skeleton(height: 120);
      return Watch.list(
        viewModel.rows,
        itemKey: viewModel.keyOf,
        each: (row) => ListTile(
          title: row.text(viewModel.title),
          trailing: Watch(
            viewModel.cancelling.withArg(row.key),
            builder: (busy) => busy
                ? const Text('Cancelling…')
                : TextButton(
                    // A method of the ViewModel, never a closure.
                    onPressed: viewModel.cancel.run.withArg(row.key),

                    child: const Text('Cancel'),
                  ),
          ),
        ),
      );

    },
  );

}
La parte del ViewModel que vive en el navegador: query lee, command escribe, state guarda lo que el usuario cambia y derived calcula a partir de ellos.
class OrdersViewModel extends ChangeNotifier {
  OrdersViewModel({required OrdersRepository ordersRepository})
    : _ordersRepository = ordersRepository {
    load = Command0(_load)..execute();
    cancel = Command1(_cancel);
  }



  final OrdersRepository _ordersRepository;



  late final Command0 load;
  late final Command1<void, String> cancel;



  List<Order> _orders = [];
  List<Order> get orders => _orders;



  Future<Result<void>> _load() async {
    final result = await _ordersRepository.list();
    switch (result) {
      case Ok<List<Order>>():
        _orders = result.value;
        notifyListeners();
        return const Result.ok(null);
      case Error<List<Order>>():
        return Result.error(result.error);

    }

  }



  Future<Result<void>> _cancel(String id) async {
    final result = await _ordersRepository.cancel(id);
    if (result is Error<void>) return result;
    return _load();
  }
}
class OrdersViewModel extends ThorState {
  // query: reads from the repository, on the server.
  final list = query(listOrders);



  // command: writes through the repository; list comes back refreshed.
  final cancel = commandWith(
    cancelOrder,
    invalidates: (OrdersViewModel s) => [s.list],
  );



  // A state field: what the user changes in the browser.
  final onlyOpen = state(false);



  // A computed value: derived from the others, never a second list.
  late final visible = derived(
    () => [
      for (final o in list.data.value ?? const <Order>[])
        if (!onlyOpen.value || o.isOpen) o,
    ],
  );



  List<Order> rows() => visible.value;
  String keyOf(Order o) => o.id;
  String title(Order o) => o.title;
  bool cancelling(String id) => cancel.pendingFor(id);
  void setOnlyOpen(bool value) => onlyOpen.value = value;

}


final orders = OrdersViewModel();
La otra mitad del ViewModel vive en el servidor: load trae los datos antes de renderizar y una acción recibe el formulario. Lanzar NotFound o Redirect decide qué página se ve.
// The router builds the ViewModel and starts its load.
GoRoute(
  path: '/orders/:id',
  builder: (context, state) => OrderView(
    viewModel: OrderViewModel(
      ordersRepository: context.read(),
      id: state.pathParameters['id']!,
    )..load.execute(),

  ),

)
class OrderPage extends ThorPage<Order> {
  const OrderPage();



  // Runs on the server before the page is rendered. find() throws NotFound
  // when there is no such order: the page is the 404.
  @override
  Future<Order> load(PageRequest request) =>
      request.context.get(ordersKey).find(request.param('id'));



  // An action: a form posts to it, with or without JavaScript.
  Future<ActionResult?> cancel(PageRequest request) async {
    await request.context.get(ordersKey).cancel(request.param('id'));
    return Redirect(ordersRoute.link()).flash('Order cancelled');
  }



  @override
  Widget build(BuildContext context, PageState<Order> state) => Column(
    children: [
      Text(state.data.title),
      Form(
        child: FilledButton(onPost: cancel, child: const Text('Cancel')),

      ),

    ],
  );
}

La vista

La vista muestra lo que expone el ViewModel y le pasa los eventos del usuario. Solo contiene lógica de presentación: un if para mostrar u ocultar, el layout, una animación.

lib/modules/orders/widgets/orders_view.dart
import 'package:thor_ui/thor_ui.dart';

import '../state/orders_view_model.dart';

class OrdersView extends StatelessWidget {
  const OrdersView({super.key, required this.viewModel});

  final OrdersViewModel viewModel;

  @override
  Widget build(BuildContext context) => Watch.list(
    viewModel.rows,
    itemKey: viewModel.keyOf,
    each: (row) => ListTile(
      title: row.text(viewModel.title),
      trailing: TextButton(
        onPressed: viewModel.cancel.run.withArg(row.key),
        child: const Text('Cancel'),
      ),
    ),
  );
}
Diferencia con Flutter

Una vista es siempre un StatelessWidget; no hay setState. Lo que la vista recuerda vive en el ViewModel, y cada callback es un método del ViewModel, nunca un closure.

El ViewModel

Un ViewModel (ThorState) es una clase con cuatro tipos de miembro: queries, commands, campos de estado y valores calculados. Cumple el papel del ChangeNotifier de Flutter.

lib/modules/orders/state/orders_view_model.dart
import 'package:thor_ui/thor_ui.dart';

import '../data/order.dart';
import '../data/orders_scope.dart';

class OrdersViewModel extends ThorState {
  // query: reads from the repository, on the server.
  final list = query(listOrders);

  // command: writes through the repository; list comes back refreshed.
  final cancel = commandWith(
    cancelOrder,
    invalidates: (OrdersViewModel s) => [s.list],
  );

  // A state field: what the user changes in the browser.
  final onlyOpen = state(false);

  // A computed value: derived from the others, never a second list.
  late final visible = derived(
    () => [
      for (final o in list.data.value ?? const <Order>[])
        if (!onlyOpen.value || o.isOpen) o,
    ],
  );

  List<Order> rows() => visible.value;
  String keyOf(Order o) => o.id;
  String title(Order o) => o.title;
  bool cancelling(String id) => cancel.pendingFor(id);
  void setOnlyOpen(bool value) => onlyOpen.value = value;
}

final orders = OrdersViewModel();
NecesitasEscribesEn Flutter
Leer datos del servidorquery(fn), queryWith(fn, arg: x)Command0 y el repositorio
Escribir y actualizar la listacommandWith(fn, invalidates: …)Command1
Recordar lo que cambia el usuariostate(value)un campo y notifyListeners()
Un valor calculadoderived(() => …)un getter
Saber si espera o fallócancel.pending, cancel.error, list.loadingcommand.running, command.error

La instancia es una variable final de nivel superior, y la vista la recibe por el constructor: OrdersView(viewModel: orders). invalidates: recibe el propio ViewModel porque el campo se declara antes de que exista this. Los tipos que caben en un ViewModel están en Estado.

Diferencia con Flutter

El State<T> de Flutter pertenece a un widget y desaparece con él. Un ViewModel pertenece a la pantalla y lo comparten varias vistas, por eso nunca se declara dentro de un widget.

Carga, error y datos

QueryBuilder es el FutureBuilder de una query: el servidor renderiza una variante por estado y el navegador cambia entre ellas.

lib/modules/orders/widgets/orders_panel.dart
import 'package:thor_ui/thor_ui.dart';

import '../state/orders_view_model.dart';
import 'orders_view.dart';

class OrdersPanel extends StatelessWidget {
  const OrdersPanel({super.key});

  @override
  Widget build(BuildContext context) => QueryBuilder(
    query: orders.list,
    builder: (context, snapshot) {
      if (snapshot.hasError) return QueryError(orders.list);
      if (!snapshot.hasData) return const Skeleton(height: 120);
      return OrdersView(viewModel: orders);
    },
  );
}
Diferencia con Flutter

snapshot.error es el String que el servidor dejó pasar, no un Object. Como el builder se ejecuta en el servidor, QueryError(orders.list) muestra ese mensaje y lo actualiza en el navegador.

Carga de la página y acciones

La otra mitad del ViewModel está en la página, en el servidor: load trae los datos antes de renderizar y una acción recibe un formulario. Lanzar NotFound o Redirect decide qué página se ve.

lib/modules/orders/pages/order_page.dart
import 'package:thor_server/thor_server.dart';
import 'package:thor_ui/router.dart';
import 'package:thor_ui/thor_ui.dart';

import '../data/order.dart';
import '../data/orders_scope.dart';
import '../orders_routes.dart';

class OrderPage extends ThorPage<Order> {
  const OrderPage();

  // Runs on the server before the page is rendered.
  @override
  Future<Order> load(PageRequest request) =>
      request.context.get(ordersKey).find(request.param('id'));

  // A form posts here, with or without JavaScript.
  Future<ActionResult?> cancel(PageRequest request) async {
    await request.context.get(ordersKey).cancel(request.param('id'));
    return Redirect(ordersRoute.link()).flash('Order cancelled');
  }

  @override
  Widget build(BuildContext context, PageState<Order> state) => Column(
    children: [
      Text(state.data.title),
      Form(
        child: FilledButton(onPost: cancel, child: const Text('Cancel')),
      ),
    ],
  );
}

Si el pedido no existe, el repositorio lanza NotFound y la página muestra el 404 sin código adicional en load. El repositorio llega a la petición por un middleware (Capa de datos).

Elegir dónde se cargan los datos

QuieresUsaSin JavaScript
Los datos de la primera carga, el 404 o una redirecciónloadsí
Volver a pedir sin recargar, o un dato que no hace falta al renderizarquery, queryWith o query(fn, ssr: false)no
Cambiar algo y actualizar la listacommand con invalidates:no
Un formulario con validaciónuna acción (onPost, onValid)sí

Si la página debe funcionar sin JavaScript, la acción es la base y el command la mejora (Servidor y acciones).

Cuidado

load, las acciones y las funciones de una query o un command corren en el servidor, y cualquier usuario que abra la página puede llamarlos. Autoriza dentro de cada uno con el usuario de la petición; en una query o un command, la petición es PageRequest.current.
